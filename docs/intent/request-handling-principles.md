# AI Butler의 요청 처리 원칙

[AI Butler의 목표](ai-butler.md)를 요청 처리에 적용할 때 따르는 용어와 원칙이다. 채널, 화면, 구현 수단과 무관하게 정해 둔 내용이며, 스펙을 쓸 때 이 문서를 근거로 삼는다.

## 용어

- **요청** — 요청자가 사용자에게 바라는 결과 하나이자 목록에서 추적하는 단위다. 같은 부탁이 여러 채널과 기록에 걸쳐 있어도 요청은 하나이고, 접수한 뒤에 이어지는 대화와 작업, 기록도 그 요청에 속한다. 사용자가 비서에게 직접 맡긴 일도 요청이며, 이때 요청자는 사용자다.
- **작업** — 요청을 끝내려고 하는 일 하나. 작업마다 담당이 있고, 작업 사이에는 선후와 의존이 있을 수 있다.
- **사용자** — 비서를 쓰는 사람. 요청을 받은 당사자이고 비서에게 맡길 범위를 정한다.
- **요청자** — 사용자에게 부탁한 사람. 요청을 바꾸거나 철회할 수 있다. 결과를 받을 사람이 따로 있으면 약속한 결과에 적는다.
- **담당** — 작업을 맡은 주체. 사용자, 다른 사람이나 팀, 에이전트일 수 있고, 사람일 때는 담당자라고도 쓴다.
- **AI 팀원** — 비서가 이름과 역할로 식별하고 여러 요청에서 다시 일을 맡길 수 있는 에이전트다.
- **차례** — 요청이나 작업이 나아가려면 지금 행동해야 하는 주체.
- **상태** — 요청이나 작업이 지금 놓인 단계. 진행 중인지, 다른 주체를 기다리는지, 보류했는지, 끝났는지를 구분한다.
- **준비** — 사용자가 바로 판단하고 조치할 수 있도록 관련 자료를 모으고 조회해 요청에 붙여 두는 일. 읽기만 한다.

## 접수와 묶기

비서는 연결된 채널에서 사용자에게 들어온 요청을 스스로 찾아 분류하고 업무 목록에 올린다. 요청을 올릴 때는 목록에서 바로 알아볼 수 있는 제목을 붙이고, 요청의 내용이 달라지면 제목도 맞춰 고친다. 대화의 맥락을 살펴도 처리할 요청인지, 이미 있는 요청에 속하는지, 누구 차례인지 판단하기 어려우면 사용자에게 모호한 점을 짚어 묻고 답을 목록에 반영한다. 묻는 동안에도 그 요청은 목록에 보이고, 무엇이 정해지지 않았는지 함께 드러난다.

비서는 새로 들어온 대화와 작업, 기록이 이미 있는 요청에 속하는지부터 살핀다. 이 판단은 접수할 때만이 아니라 요청이 끝날 때까지 계속하며, 사용자가 직접 진행한 작업도 대상이다. 이미 있는 요청과 같은 부탁으로 확인되면 하나로 합친다. 어느 요청에 속하는지 판단하기 어려우면 추측으로 정하지 않고 사용자에게 묻는다. 사용자가 묶음을 합치거나 나누거나 옮기면 그대로 반영하고, 비슷한 대화와 작업을 묶을 때 바로 활용한다.

## 상태와 긴급도·중요도

비서는 실제 진행 상황과 기록에 따라 요청과 작업의 상태를 옮긴다. 다른 주체의 조치를 기다리는 대기와 사용자가 멈춰 둔 보류는 구분해 보여 준다. 다른 곳으로 넘긴 일도 이들과 구분해 보여 준다. 어떤 작업이 대기나 보류 중이어도 그와 독립적인 작업은 진행할 수 있는 일로 드러낸다. 상태의 이름과 전체 목록은 스펙에서 정한다.

비서는 요청 내용과 요청자, 기한을 근거로 긴급도와 중요도를 매겨 요청과 함께 보여 준다.

사용자는 실행을 맡겼는지와 무관하게 언제든 상태와 긴급도, 중요도, 처리할 순서를 직접 정할 수 있고, 사용자가 정한 값은 비서의 판단보다 앞선다. 그 값을 얼마나 유지하는지는 사용자가 사실을 바로잡은 것인지 지시한 것인지에 따라 다르다. 대기나 진행 중처럼 지금 상태를 바로잡은 것은 그 시점의 사실을 고친 것이어서, 이후 새 기록이 생기면 비서가 다시 상태를 옮긴다. 보류, 긴급도와 중요도, 처리할 순서, 묶음, 직접 표시한 완료는 사용자의 지시여서 사용자가 바꿀 때까지 유지한다. 요청의 제목과 요청자도 사용자가 정한 값을 유지한다. 약속한 결과와 기한은 사용자가 바로잡은 뒤에도 요청자가 요청을 바꾼 새 기록이 생기면 비서가 갱신하되, 사용자가 해 주기로 한 적 없는 범위는 사용자에게 확인한다.

보류는 사용자가 풀거나 사용자가 미리 정한 조건이 이루어질 때까지 둔다. 다른 팀의 답이 오면 재개하라고 했다면 그 답을 확인했을 때 재개한다. 보류는 목록에 바로 반영한다. 영향을 받는 사람과 에이전트에게 알리는 일은 맡긴 범위 안에서만 하고, 그 밖에서는 알려야 할 대상이 있다는 점을 목록에 드러낸다.

사용자가 고친 긴급도와 중요도는 비슷한 요청을 분류할 때 반영한다. 사용자가 처리할 순서를 따로 정하면 긴급도와 중요도는 그대로 두고 그 순서를 따른다.

## 맡긴 범위와 맡기지 않은 범위

맡긴 범위는 사용자가 직접 맡겼거나 업무 지침에서 미리 맡겨 둔 범위다. 그 안에서 비서는 요청 내용, 사전에 제공된 업무·시스템 정보, 대화에서 한 약속, 실제 진행 상황을 바탕으로 다음 작업과 담당을 정한다.

맡긴 범위 안에서 비서는 요청자와 담당자, 결과를 알리기로 한 사람에게 직접 연락할 수 있다. 보낸 내용은 요청에 남겨 사용자가 확인할 수 있게 하고, 현재 권한과 승인 조건, 사용자가 맡기로 한 역할을 지킨다.

사용자가 일이 진행되는 중에 특정 작업을 보류하거나 방향을 바꾸면, 비서는 목록과 후속 작업에 반영하고 맡긴 범위 안에서 영향을 받는 사람과 에이전트에게 변경 내용을 전달한다.

사용자의 판단이 필요하거나 업무 환경과 시스템의 제약으로 사람이 직접 처리해야 하는 단계에서는 비서가 담당자에게 필요한 결정이나 조치를 요청한다. 누구에게 무엇을 요청했는지 목록에 남기고, 기다리는 동안에도 독립적인 일은 계속 진행한다. 다른 사람 또는 에이전트의 조치가 늦어져 후속 작업이나 약속한 일정에 영향이 생기면 비서가 먼저 진행 상황을 확인하고, 사용자의 판단이 필요하면 알린다. 필요한 답이나 처리 결과를 확인하면 별도 지시 없이 후속 작업을 이어 간다.

맡기지 않은 요청에서는 접수와 분류, 기록 확인, 목록 갱신, 준비까지 한다. 준비는 관련 대화와 티켓을 모아 요약하고 대상 고객이나 결제 건, 배포 기록처럼 판단에 필요한 정보를 조회해 요청에 붙여 두는 일로, 비서에게 주어진 조회 권한 안에서 읽기만 한다. 사용자가 다음에 할 조치가 알려지면 차례가 오기 전에도 준비하고, 차례가 오면 최신 내용으로 다시 확인한다. 무언가를 바꾸는 작업을 실행하거나 다른 사람에게 연락하는 일은 맡긴 범위 안에서만 한다. 요청이 맡긴 범위에 드는지 분명하지 않으면 실행하기 전에 사용자에게 묻는다.

## AI 팀원에게 작업 맡기기

사용자는 비서에게 요청과 변경 사항을 전하고, 비서가 각 팀원에게 직접 작업을 배정한다. 독립적인 작업은 역할에 맞는 팀원들에게 병렬로 맡긴다.

비서는 팀원별로 역할, 작업 방법을 담은 지침, 사용할 수 있는 도구와 권한을 관리한다. 기존 팀원 중 적임자가 없으면 비서가 역할과 지침을 정해 팀원을 만들고, 이미 허용된 도구와 권한 중 작업에 필요한 것을 부여한다. 새 팀원을 만들거나 기존 팀원의 설정을 바꿀 때도 사용자가 직접 또는 업무 지침으로 맡긴 범위와 승인 조건을 적용한다. 추가 접근 권한이나 실행 승인이 필요하면 비서는 사용자에게 무엇이 필요한지 알리고, 해당 권한이나 승인이 확인되면 그 작업을 이어 간다.

비서는 작업을 배정할 때 어느 요청에서 무엇을 맡겼고 어떤 결과를 받아야 하는지 기록한다.

팀원의 진행 상황과 대기 사유, 사용자가 바꾼 지시, 결과와 근거는 해당 작업에 남긴다. 특정 작업을 보류하라는 지시는 그 작업에만 적용하고, 비서의 판단을 바로잡은 정정은 다음 분류와 실행에도 반영한다. 모델 호출과 작업 수행에는 기존 실행 도구를 활용할 수 있다. 팀원과 작업 기록은 비서가 직접 관리하므로 실행이 중단되거나 도구가 바뀌어도 같은 팀원에게 남은 일을 이어서 맡길 수 있다.

## 약속한 결과

약속한 결과는 요청을 완료했다고 볼 기준이다. 해 주기로 한 일과 함께 그 결과를 누구에게 알리기로 했는지도 여기에 들어간다. 따로 알릴 것이 없는 요청은 조치한 기록으로 완료한다. 비서는 요청 내용과 대화에서 한 약속을 근거로 이를 정해 요청과 함께 보여 주고, 사용자는 언제든 바로잡을 수 있다. 사용자가 따로 약속하지 않았다면 요청 내용이 기준이고, 요청자에게 일부만 해 주기로 했다면 그 범위가 기준이다. 사용자가 비서에게 실행을 얼마나 맡겼는지는 이 기준을 바꾸지 않는다. 요청자가 요청을 바꾸면 비서는 약속한 결과와 영향을 받는 작업을 갱신하되, 사용자가 해 주기로 한 적 없는 범위는 사용자에게 확인한다.

개별 작업이 끝나도 요청자에게 약속한 일이 남아 있으면 계속 추적한다. 이미 결과를 전달했다면 그 기록으로 요청을 완료해 중복 회신을 막는다. 완료한 요청에는 그 근거를 남기고, 완료 목록에서도 무엇을 어떻게 해결했는지 확인할 수 있게 한다.

## 약속한 결과 없이 끝나는 요청

요청은 약속한 결과를 이루지 않고 끝나기도 한다. 요청자가 철회했거나, 사용자가 맡지 않기로 했거나, 요청 전체를 다른 사람이나 팀에 넘긴 경우다. 맡지 않거나 넘기는 결정은 사용자가 한다. 비서는 철회한 기록이나 그 결정이 요청자에게 전달된 기록을 확인한 뒤 사유와 함께 요청을 닫는다. 넘긴 요청은 넘겨받는 쪽이 인수한 기록까지 확인한 뒤에 닫는다. 철회나 전달, 인수가 기록이 남지 않는 방법으로 이루어졌으면 사용자가 직접 확인해 닫을 수 있고, 이때 무엇을 사용자 확인으로 닫았는지 남긴다. 맡지 않거나 넘기겠다는 결정만으로는 닫지 않는다. 이렇게 닫은 요청은 완료와 구분해 보여 준다.

철회가 확인되거나 사용자가 맡지 않거나 넘기기로 정하면, 비서는 요청을 닫기 전이라도 맡긴 범위 안에서 영향을 받는 사람과 에이전트에게 알려 진행 중인 실행을 보류한다. 그 밖의 작업은 멈춰야 한다는 점을 목록에 드러낸다. 이미 끝냈거나 멈출 수 없는 조치는 요청에 남기고, 사용자가 계속하라고 하면 계속한다.

## 확인과 시정

비서는 기록에서 확인한 것만 스스로 끝난 일로 표시한다. 아직 확인되지 않은 것은 확인된 만큼만 반영하고 계속 확인한다. 기록이 서로 어긋나거나 기록에 접근할 수 없어 스스로 풀 수 없을 때는 추측으로 채우지 않고, 무엇을 확인하지 못했는지 목록에 드러내고 사용자에게 묻는다.

사용자나 다른 팀이 처리한 일도 업무 기록에서 결과를 확인해 목록에 반영하고, 팀원이 붙인 배포 기록이나 발송 기록 등에서 확인된 부분도 반영한다. 비서는 사용자와 다른 담당이 마친 일까지 모아 요청자에게 약속한 결과와 대조하고, 남은 일이 있으면 맡긴 범위 안에서 후속 작업을 배정한다.

사용자가 작업이나 요청을 끝났다고 직접 표시하면 비서는 기록 확인을 기다리지 않고 반영한다. 이때 비서가 기록에서 확인한 완료와 사용자가 직접 표시한 완료를 구분해 남긴다. 이후 기록이 사용자의 표시와 어긋나는 것을 알게 되어도 스스로 되돌리거나 작업을 다시 시작하지 않는다. 어긋난 점은 요청에 남기고, 약속한 결과에 영향이 있을 때 사용자에게 알린다.

수행 결과가 약속한 결과와 어긋나면 비서는 맡긴 범위 안에서 후속 작업을 맡겨 바로잡고, 그 밖에서는 어긋난 점과 필요한 조치를 목록에 드러낸다. 사용자가 직접 끝났다고 표시한 일은 여기에 들지 않고 앞 문단을 따른다. 같은 문제가 되풀이되면 더 반복하지 않고 어디서 막혔는지 사용자에게 알린다. 비서의 분류나 반영이 틀렸음을 알게 되면 목록을 고치고, 그 때문에 이미 나간 연락이나 실행이 있으면 사용자에게 알린다.

## 정정의 반영

사용자가 묶음, 제목, 차례, 상태, 긴급도와 중요도, 약속한 결과처럼 비서의 판단을 바로잡으면, 비서는 그 요청에 바로 반영하고 비슷한 요청을 분류할 때도 바로 반영한다. 추적만 쓰는 단계에서도 그렇게 한다. 보류나 처리할 순서처럼 그 요청에만 해당하는 지시는 다른 요청으로 넓히지 않는다. 사용자는 어떤 정정 때문에 판단이 달라졌는지 확인하고 되돌릴 수 있다.

비서의 판단과 사용자의 정정은 바뀐 내역을 모두 이력으로 남겨, 나중에 판단과 절차를 고칠 때 비교할 수 있게 한다.
