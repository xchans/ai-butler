# AI Butler의 목표

AI Butler는 사용자의 할 일 목록을 관리하고 각 요청의 진행을 조율하는 개인 업무 비서다. 비서는 여러 채널로 들어온 요청을 챙기고, 사용자가 판단하거나 직접 처리할 일을 미리 준비한다. 사용자가 직접 또는 업무 지침으로 실행을 맡기면, 해당 업무에 특화된 에이전트인 AI 팀원이 작업을 수행한다. 비서는 팀원에게 일을 배정하고 그 결과를 확인하며, 요청이 끝날 때까지 전체 진행을 책임진다.

## 풀려는 문제

요청은 여러 경로로 들어오고, 하나의 요청은 여러 할 일이 있을 수 있다. 지금은 사용자가 요청마다 어디까지 진행됐는지 기억하고, 다른 사람에게 맡긴 일을 확인하고, 마지막에는 요청자에게 약속한 결과가 이루어졌는지까지 챙겨야 한다. AI Butler가 이 과정을 챙기면 사용자는 자신의 판단이 필요하거나 직접 처리해야 하는 일에 집중할 수 있다.

AI Butler는 사용자의 개인 업무 목록을 관리한다. 비서는 새 요청이 들어오면 목록에 올리고, 일이 진행되면 그 상태를 갱신한다. 사용자가 비서에게 직접 부탁한 일도 같은 업무 목록에 등록한다. 사용자는 목록을 따로 정리하지 않아도 각 요청의 현재 상태를 알 수 있고, 실제와 다른 부분만 바로잡으면 된다.

## 전체 업무를 한눈에 보고 각 요청을 접수부터 완료까지 추적한다

비서는 연결된 채널을 지속적으로 살펴 사용자가 처리할 요청을 찾아 분류하고, 새 요청을 업무 목록에 등록하면 사용자에게 알린다. 뒤에 이어지는 대화와 작업, 기록은 같은 요청에 묶는다. 사용자가 직접 진행한 일도 마찬가지다. 사용자는 비서에게 실행을 맡기기 전에도 어떤 요청이 들어왔고 누구의 행동이 필요한지 확인할 수 있다.

사용자는 원래 대화를 다시 열지 않고 목록만 보고도 끝난 일과 남은 일, 다음에 행동할 주체를 구분해 일을 이어갈 수 있어야 한다. 여러 요청 가운데 지금 내 차례인 일이 무엇이고 그중 무엇부터 손댈지도 목록에서 알 수 있어야 한다. 같은 요청 안에서 일부 작업이 다른 주체를 기다리고 있어도 지금 내가 할 수 있는 작업은 목록에 드러나야 한다. 요청마다 어디서 어떤 부탁을 받았는지, 어떤 작업이 있고 각각 누가 맡아 어디까지 진행했는지 확인할 수 있어야 한다.

요청과 작업이 늘어나도 한 요청의 연속인 일이 별개의 일로 흩어지지 않아야 한다. 묶음이 틀리면 차례와 상태도 틀리게 보인다.

## 사용자 차례인 일은 바로 판단하고 조치할 수 있게 준비해 둔다

비서는 사용자 차례인 일과 다음에 사용자 차례가 될 일에 판단과 조치에 필요한 자료를 미리 붙여 둔다. 사용자는 일을 열었을 때 자료를 찾으러 다니지 않고 바로 판단하거나 조치할 수 있어야 한다. 준비는 읽기만 하는 일이어서 실행을 맡겼는지와 관계없이 한다.

## 비서가 작업을 배정하고 AI 팀원이 수행한 결과를 확인한다

사용자는 요청 전체나 그중 일부를 맡길 수 있다. 비서는 맡긴 범위 안에서 다음 작업을 정하고, 각 작업에 맞는 AI 팀원에게 할 일과 기대하는 결과를 전달한다. 서로 독립적인 작업은 여러 팀원에게 병렬로 맡긴다. 각 팀원은 배정받은 작업을 수행하고 결과와 그 근거를 비서에게 돌려준다.

비서는 팀원마다 역할과 지침, 쓸 수 있는 도구와 권한을 관리한다. 작업을 맡을 팀원이 없으면 이미 허용된 도구와 권한 안에서 새 팀원을 만든다. 팀원을 만들거나 설정을 바꿀 때도 맡긴 범위와 승인 조건을 지키고, 추가 권한이나 승인이 필요하면 사용자에게 알린 뒤 확인되면 그 작업을 이어 간다. 팀원과 작업 기록은 비서가 관리하므로 작업을 보류했거나 실행이 중단돼도 같은 팀원에게 남은 일을 이어서 맡길 수 있다.

비서는 각 작업이 어디까지 진행됐고 무엇을 기다리는지 확인해 목록을 갱신한다. 팀원이 작업을 마치고 결과를 보내면 비서는 근거를 살펴 확인된 단계만 완료로 표시한다. 그러고 나서 어느 팀원의 어떤 작업이 끝났고 결과가 어땠는지 사용자에게 직접 회신한다. 요청에 남은 일이 있으면 회신에 함께 적고, 맡긴 범위 안에서 후속 작업을 배정한다.

맡긴 범위 안에서 비서는 요청자와 담당자, 결과를 알리기로 한 사람에게 직접 연락한다. 다른 사람이나 팀의 결정이나 조치가 필요한 단계에서는 그 담당자에게 요청하고, 누구에게 무엇을 요청했는지 목록에 남긴다. 필요한 답이나 처리 결과를 확인하면 별도 지시 없이 맡긴 후속 작업을 이어 간다. 보낸 내용은 요청에 남겨 사용자가 확인할 수 있게 한다.

AI 팀원이나 다른 담당자의 작업이 늦어져 후속 작업이나 기한에 영향이 생기면 비서가 먼저 상황을 확인한다. 사용자의 판단이나 승인, 직접 조치가 필요한 단계에 이르면 무엇을 해야 하는지 사용자에게 알린다. 사용자가 작업을 보류하거나 방향을 바꾸면 비서가 변경 사항을 맡긴 범위 안에서 영향을 받는 사람과 에이전트에게 전달한다. 사용자는 각 팀원을 찾아가지 않아도 목록에서 진행 상황과 결과를 확인할 수 있어야 한다.

## 약속한 결과가 이루어질 때까지 추적한다

요청의 완료 기준은 요청자에게 약속한 결과다. 비서는 요청 내용과 대화에서 한 약속을 근거로 약속한 결과를 정해 요청과 함께 보여 주고, 사용자는 언제든 바로잡을 수 있다. 비서는 AI 팀원과 사용자, 다른 담당이 마친 일을 모아 이 기준과 대조한다. 결과를 알리기로 한 사람이 있으면 맡긴 범위 안에서는 비서가 전달하고, 누가 전달했든 그 사람에게 전달된 기록까지 확인한다. 이미 전달된 결과는 다시 보내지 않는다. 약속한 결과가 이루어진 것을 확인하면 사용자에게 알리고 요청을 닫는다. 사용자가 비서에게 실행을 얼마나 맡겼는지는 이 기준을 바꾸지 않는다.

사용자는 완료 표시를 믿을 수 있어야 한다. 비서는 기록에서 확인한 것만 스스로 끝난 일로 표시하고, 사용자가 직접 끝났다고 표시한 일은 그와 구분해 보여 준다. 완료한 요청에서는 무엇을 어떻게 해결했는지와 그 근거를 나중에도 확인할 수 있어야 한다. 철회나 이관처럼 약속한 결과 없이 끝난 요청은 완료와 구분해 보여 준다.

## 실제 처리 경험에서 배운다

비서는 기존 스킬과 지침에서 출발해 자신의 판단을 사용자의 정정, 실제 행동, 처리 결과와 비교하고 판단과 절차를 고쳐 간다. 사용자가 한 번 바로잡은 판단은 비슷한 요청에서 다시 바로잡지 않아도 되어야 하고, 비서의 누락으로 사용자가 다시 일하는 경우가 줄어야 한다.

사용자의 정정과, 사용자와 함께 돌아보며 정한 변화는 처음부터 다음 유사 업무에 적용한다. 비서가 스스로 돌아보는 일만 마지막에 만든다.

배운 것이 비서의 권한을 넓히지는 않는다. 판단이나 절차가 달라져도 현재 권한, 승인 조건, 사용자가 맡기로 한 역할은 그대로 지킨다. 사용자는 어떤 경험 때문에 판단이나 절차가 달라졌는지 확인하고 바로잡을 수 있다.

## 판단이 부딪힐 때 앞세우는 것

- **조용히 틀리기보다 묻는다.** 목록이 틀리면 사용자는 원래 대화를 다시 열어 확인해야 한다. 맥락과 기록을 살펴도 판단할 수 없는 것은 추측으로 정하지 않고 사용자에게 묻는다. 대신 사용자의 답과 정정을 비슷한 요청의 판단에 반영해 같은 질문을 줄인다.
- **사용자가 정한 것이 비서의 판단보다 앞선다.** 사용자는 실행을 맡겼는지와 무관하게 언제든 요청과 작업의 묶음, 차례, 상태, 긴급도와 중요도, 처리할 순서, 약속한 결과를 직접 정할 수 있다.
- **일을 끝내는 것보다 맡긴 범위를 지키는 것이 앞선다.** 범위 밖에서 필요한 조치는 실행하지 않고 목록에 드러낸다.

## 하지 않는 일

- 회의 일정을 잡거나 캘린더를 조작하지 않는다. 비서가 챙기는 일정은 요청의 기한이다.
- 여럿이 함께 쓰는 업무 도구가 아니다. 다른 사람은 요청자나 담당으로 등장할 뿐 목록을 함께 쓰지 않는다.
- 사용자가 직접 맡겼거나 업무 지침에서 미리 맡겨 둔 범위 밖에서는 추적과 준비까지만 한다. 무언가를 바꾸는 작업을 실행하거나 다른 사람에게 연락하지 않는다.
- 팀원끼리 직접 일을 넘기거나 AI 팀 전체에 일을 맡기는 방식은 지금 목표에 넣지 않는다. 개별 팀원에게 배정한 경험을 바탕으로 추후 검토한다.

## 만드는 순서

AI Butler가 하는 일은 요청 추적, 실행 조율, 경험에서 배우기로 나뉘고 셋 모두 제품의 큰 부분이다. 만드는 순서는 추적, 실행 조율, 배우기다. 추적은 사용자 차례인 일을 준비하고 사용자의 정정을 다음 분류에 반영하는 데까지를 포함하며, 실행 조율과 배우기 없이도 쓸 수 있어야 한다. 마지막에 만드는 배우기는 비서가 스스로 경험을 돌아보고 판단과 절차를 고치는 일이다.

## 잘 되고 있는지 확인하는 기준

초기에는 사용자와 비서가 실제 요청을 골라 어디서 사용자 판단이 필요했고 다음에는 무엇을 다르게 할지 함께 돌아본다.

- **분류** — 이어지는 일을 같은 요청으로 묶었는가. 누구 차례인지 정확히 짚었는가.
- **준비** — 사용자가 일을 열었을 때 붙어 있는 자료만으로 판단하거나 조치할 수 있었는가. 사용자가 다시 조회한 정보가 있었는가.
- **완료 판단** — 비서가 완료로 닫은 요청에서 약속한 결과가 실제로 이루어졌는가. 회신이 남았는데 닫거나 이미 전달한 결과를 다시 보낸 적이 있는가.
- **실행 조율** — 비서가 팀원의 결과를 확인하고 남은 작업을 이어서 배정했는가. 사용자가 직접 팀원을 찾아 진행을 확인하거나 비서의 누락으로 다시 일해야 했는가.

분류와 준비, 완료 판단은 추적의 회고에서, 실행 조율은 실행 조율의 회고에서 다룬다. 이미 적용한 변화가 추적과 실행 조율에서 효과가 있었는지도 확인한다. 사용자는 이렇게 살핀 결과를 근거로 추적과 실행 조율 각각의 회고를 비서에게 맡길 시점을 판단한다.

용어의 정의와 요청을 처리할 때 따르는 원칙은 [요청 처리 원칙](request-handling-principles.md)에, 이 목표를 실제 업무에 적용한 예시는 [요청 처리 사례](../ideas/request-handling-cases.md)에 정리한다.
