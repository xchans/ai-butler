# AI Butler의 목표

AI Butler는 여러 경로로 들어온 요청을 한곳에서 관리하는 개인 업무 비서다. 사람 비서가 대표에게 온 연락을 먼저 챙기고 필요한 자료를 미리 준비해 대표가 판단과 실제 조치에 집중하게 하듯, AI Butler는 사용자에게 들어온 요청을 모두 약속한 결과가 이루어지거나 다른 사유로 끝날 때까지 추적하고 사용자 차례인 일을 준비해 둔다. 사용자가 실행을 맡기면 비서는 역할에 맞는 AI 팀원에게 작업을 배정하고, 요청자에게 약속한 결과가 전달될 때까지 전체 진행을 책임진다.

요청은 여러 경로로 흩어져 들어오고, 요청 하나가 여러 작업과 여러 담당자로 나뉘어 오래 이어진다. 그동안 전체 상태를 기억하고, 남에게 맡긴 일을 확인하고, 약속한 결과가 전달됐는지 챙기는 일은 모두 사용자 몫이다. AI Butler는 이 일을 넘겨받아, 사용자가 판단과 직접 해야 하는 조치에만 시간을 쓰게 한다.

업무 목록은 사용자 한 사람의 것이고, 사용자가 입력하지 않아도 맞아야 한다. 요청을 목록에 올리고 상태를 옮기는 일은 비서가 하고, 사용자는 틀린 것을 바로잡는다. 다른 사람은 요청자나 담당으로 등장할 뿐 목록을 함께 쓰지 않는다.

AI Butler가 하는 일은 요청 추적, 실행 조율, 경험에서 배우기로 나뉘고 셋 모두 제품의 큰 부분이다. 만드는 순서는 추적, 실행 조율, 배우기다. 추적은 사용자 차례인 일을 준비하고 사용자의 정정을 다음 분류에 반영하는 데까지를 포함하며, 실행 조율과 배우기 없이도 쓸 수 있어야 한다. 마지막에 만드는 배우기는 비서가 스스로 경험을 돌아보고 판단과 절차를 고치는 일이다.

## 전체 업무를 한눈에 보고 각 요청을 접수부터 완료까지 추적한다

비서는 연결된 채널에서 사용자에게 들어온 요청을 스스로 찾아 분류하고 업무 목록에 올린다. 대화의 맥락을 살펴도 처리할 요청인지, 이미 있는 요청에 속하는지, 누구 차례인지 판단하기 어려우면 사용자에게 모호한 점을 짚어 묻고 답을 목록에 반영한다. 묻는 동안에도 그 요청은 목록에 보이고, 무엇이 정해지지 않았는지 함께 드러난다. 사용자는 비서에게 실행을 맡기기 전에도 어떤 요청이 들어왔고 누구의 행동이 필요한지 확인할 수 있다.

요청을 접수한 뒤에 이어지는 대화와 작업, 기록도 비서가 같은 요청에 묶는다. 사용자가 직접 진행한 작업도 마찬가지다. 요청과 작업이 늘어나도 한 요청의 연속인 일이 별개의 일로 흩어지지 않아야 한다. 묶음이 틀리면 차례와 상태도 틀리게 보인다.

사용자는 업무 목록에서 여러 요청의 진행 상태와 지금 내 차례인 일을 한눈에 본다. 요청마다 어디서 어떤 부탁을 받았는지, 어떤 작업이 있고 각각 누가 맡아 어디까지 진행했는지 확인할 수 있다. 진행 중인 일, 다른 주체를 기다리는 일, 보류한 일, 다른 곳으로 넘긴 일은 목록에서 서로 구분된다.

비서는 요청의 긴급도와 중요도를 매겨, 사용자가 내 차례인 일 가운데 무엇부터 손댈지 알 수 있게 한다. 비서가 챙기는 일정은 요청의 기한이다. 회의 일정을 잡거나 캘린더를 조작하는 일은 목표에 들지 않는다.

비서는 실제 진행 상황에 따라 목록을 갱신한다. 작업은 한 줄로 이어지지 않고 서로 선후와 의존이 있다. 같은 요청 안에서 일부 작업이 대기 중이어도 지금 내가 할 수 있는 작업은 목록에 드러난다. 사용자는 원래 대화를 다시 열지 않고 목록만 보고도 끝난 일과 남은 일, 다음에 행동할 주체를 구분해 일을 이어갈 수 있어야 한다.

사용자는 실행을 맡겼는지와 무관하게 언제든 요청과 작업의 묶음, 상태, 긴급도와 중요도, 처리할 순서를 직접 정할 수 있다. 사용자가 정한 값은 비서의 판단보다 앞선다. 비서의 판단을 바로잡은 정정은 다음 분류에도 반영한다.

## 사용자 차례인 일은 바로 판단하고 조치할 수 있게 준비해 둔다

비서는 사용자 차례인 일과 다음에 사용자 차례가 될 일에 판단과 조치에 필요한 자료를 미리 붙여 둔다. 관련 대화와 티켓을 모아 요약하고, 대상 고객이나 결제 건, 배포 기록처럼 그 일에 필요한 정보를 조회해 둔다. 사용자는 일을 열었을 때 자료를 찾으러 다니지 않고 바로 판단하거나 조치할 수 있어야 한다.

준비는 읽기만 하는 일이어서 실행을 맡기지 않은 요청에서도 한다. 무언가를 바꾸거나 다른 사람에게 연락하는 일은 준비에 들지 않는다.

## 요청을 맡기면 비서가 결과 전달까지 스스로 이어 간다

비서는 사용자가 직접 맡겼거나 업무 지침에서 미리 맡겨 둔 범위 안에서 실행을 조율한다. 요청 내용, 사전에 제공된 업무·시스템 정보, 대화에서 한 약속, 실제 진행 상황을 바탕으로 다음 작업과 담당을 정한다.

AI 팀원은 이름과 역할이 있어 여러 요청에서 다시 일을 맡길 수 있는 에이전트다. 사용자는 비서에게 요청과 변경 사항을 전하고, 비서가 각 팀원에게 직접 작업을 배정한다. 맞는 팀원이 없으면 비서는 사용자가 맡긴 범위와 이미 허용된 도구·권한 안에서 팀원을 만들어 일을 맡긴다. 독립적인 작업은 역할에 맞는 팀원들에게 병렬로 맡긴다. 팀원끼리 직접 일을 넘기거나 AI 팀 전체에 맡기는 방식은 개별 팀원에게 배정한 경험을 바탕으로 추후 검토한다.

사용자는 요청을 열어 각 팀원이 무엇을 맡았고 어디까지 진행했는지, 무엇을 기다리는지, 결과의 근거가 무엇인지 확인할 수 있다. 비서는 팀원이 붙인 배포 기록이나 발송 기록 등에서 확인된 부분을 목록에 반영한다. 사용자와 다른 담당이 마친 일까지 모아 요청자에게 약속한 결과와 대조하고, 남은 일이 있으면 맡긴 범위 안에서 후속 작업을 배정한다.

맡기지 않은 요청에서 비서는 추적과 준비까지만 하고, 무언가를 바꾸는 작업을 실행하거나 다른 사람에게 연락하지 않는다.

사용자가 일이 진행되는 중에 특정 작업을 보류하거나 방향을 바꾸면, 비서는 목록과 후속 작업에 반영하고 맡긴 범위 안에서 영향을 받는 사람과 에이전트에게 변경 내용을 전달한다.

사용자의 판단이 필요하거나 업무 환경과 시스템의 제약으로 사람이 직접 처리해야 하는 단계에서는 비서가 담당자에게 필요한 결정이나 조치를 요청한다. 누구에게 무엇을 요청했는지 목록에 남기고, 기다리는 동안에도 독립적인 일은 계속 진행한다. 다른 사람 또는 에이전트의 조치가 늦어져 후속 작업이나 약속한 일정에 영향이 생기면 비서가 먼저 진행 상황을 확인하고, 사용자의 판단이 필요하면 알린다. 필요한 답이나 처리 결과를 확인하면 별도 지시 없이 후속 작업을 이어 간다.

맡긴 요청에서 사용자가 나서야 하는 지점은 판단과 승인, 사람이 직접 처리해야 하는 조치뿐이어야 한다.

## 약속한 결과가 이루어질 때까지 추적한다

요청의 완료 기준은 요청자에게 약속한 결과다. 사용자가 비서에게 실행을 얼마나 맡겼는지는 이 기준을 바꾸지 않는다.

사용자나 다른 팀이 처리한 일도 업무 기록에서 결과를 확인해 목록에 반영한다. 비서는 기록에서 확인한 것만 스스로 끝난 일로 표시한다. 사용자가 끝났다고 직접 표시한 일도 끝난 일이며, 사용자는 목록에서 비서가 확인한 완료와 자신이 표시한 완료를 구분해 볼 수 있다. 개별 작업이 끝나도 요청자에게 약속한 일이 남아 있으면 계속 추적한다. 이미 결과를 전달했다면 그 기록으로 요청을 완료해 중복 회신을 막는다. 완료 목록에서도 무엇을 어떻게 해결했는지 확인할 수 있어야 한다.

완료로 표시된 요청에는 그 근거가 남아 있고, 그 전인 요청은 완료로 보이지 않아야 한다. 철회나 이관처럼 약속한 결과 없이 끝난 요청은 완료와 구분해 보여 준다.

## 실제 처리 경험에서 배운다

비서는 기존 스킬과 지침에서 출발해 자신의 판단을 사용자의 정정, 실제 행동, 처리 결과와 비교한다. 이전 경험은 처음부터 다음 유사 업무에 적용한다. 사용자의 정정은 추적만 쓰는 단계에서도 다음 분류에 바로 반영하고, 실행을 맡기기 시작하면 실행에도 적용한다. 이때도 현재 권한, 승인 조건, 사용자가 맡기로 한 역할을 지킨다. 사용자는 어떤 경험 때문에 판단이나 절차가 달라졌는지 확인하고 바로잡을 수 있다.

초기에는 사용자와 비서가 실제 요청을 골라 어디서 사용자 판단이 필요했고 다음에는 무엇을 다르게 할지 함께 돌아본다. 분류에서는 이어지는 일을 같은 요청으로 묶었는지와 누구 차례인지 정확히 짚었는지, 실행에서는 비서의 누락으로 사용자가 다시 일해야 했는지를 살피고, 이미 적용한 변화의 효과도 확인한다. 사용자는 이 두 가지를 근거로 분류와 실행 각각의 회고를 비서에게 맡길 시점을 판단한다.

용어의 정의와 경계 사례에서 따르는 원칙은 [요청 처리 원칙](request-handling-principles.md)에, 이 목표를 실제 업무에 적용한 예시는 [요청 처리 사례](../ideas/request-handling-cases.md)에 정리한다.
